## Manifest Format

Actual folder keys are `SEASON/YYYYMMDD Competition Team1 vs Team2` (not a flat `YYYY-MM-DD-opponent` slug):

```json
{
  "2023-24/20231008 WSL Spurs vs Bristol City": [
    "https://cdn.jsdelivr.net/gh/EllieAtWHL/spurs-women-photo-gallery@main/2023-24/20231008 WSL Spurs vs Bristol City/001.webp",
    "https://cdn.jsdelivr.net/gh/EllieAtWHL/spurs-women-photo-gallery@main/2023-24/20231008 WSL Spurs vs Bristol City/002.webp"
  ]
}
```

## Usage

### Adding New Photo Galleries

1. Create folder in external repository: `SEASON/YYYYMMDD Competition Team1 vs Team2/` (see actual manifest format below - not a flat `YYYY-MM-DD-opponent/` slug)
2. Add optimized images (WebP/AVIF preferred)
3. Regenerate the manifest with `npm run generate-external-manifest` (there is no `predev`/`prebuild` script - manifest generation is not automatically hooked into `npm run dev`/`npm run build`)
4. Update Supabase media record with folder key as `url` field and `storage_source = 'github'`

### Development Workflow

- Manifest is **not** automatically regenerated by `npm run dev` or `npm run build` - it must be generated explicitly
- Manual regeneration: `npm run generate-external-manifest` (or `node scripts/generate-external-manifest.js`)
- CI (`.github/workflows/validate-manifest.yml`) runs `npm run generate-external-manifest` then `npm run validate-manifest` before building, on every push/PR to main
- GitHub repository serves all images via CDN
- No local image storage required
